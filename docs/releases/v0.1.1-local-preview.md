## Summary

`v0.1.1-local-preview` is intended to package the post-`v0.1.0-local-preview` local observability and release-hardening work. The main theme is better local preview operation: clearer Aethra diagnostics, terminal checks through `ignispromptctl`, stronger schema locks, conservative sustainability report polish, and read-only MCP access to existing local observability data.

The default path remains local-only and no-model friendly. It does not require Ollama, GGUF tooling, external model weights, cloud credentials, telemetry, or external services for the default build/test/smoke workflow.

## Aethra Local Preview Improvements

- Fixture mode remains the default.
- Live-local loading remains manual and loopback-oriented.
- The local preview banner makes the non-production, no-telemetry, no-cloud-by-default boundary visible.
- Overview diagnostics distinguish fixture mode, live-local readiness, successful local connection, unreachable daemon, unavailable endpoints, invalid response shapes, failed refreshes, and successful refreshes.
- Local command helpers are copy-only browser clipboard actions. Aethra does not execute commands.
- Empty states explain missing fixture/live-local data and local next steps.
- Routing Explorer and Audit Events have clearer labels, filters, and browser-local copy helpers.
- Sustainability Preview report export guidance is clearer and remains client-side only.

## CLI Improvements

- `ignispromptctl doctor` checks local preview readiness for `/health`, `/v1/status/version`, `/v1/models`, and `/v1/status/models`, with sustainability metrics as an informational check.
- `ignispromptctl sustainability --period 30d` reads `GET /v1/metrics/sustainability?period=<period>` and prints aggregate local metrics. Supported periods are `7d`, `30d`, and `90d`.
- CLI diagnostics remain local-only. They do not add telemetry, cloud calls, GitHub lookups, update checks, external coefficient lookup, persistence, uploads, model controls, runner controls, or command execution beyond local HTTP reads.

## MCP Improvements

- The experimental stdio MCP stub still uses newline-delimited JSON-RPC over stdio.
- `tools/list` now advertises `route_explain`, `audit_events`, `status_version`, and `sustainability_summary`.
- `audit_events` returns recent local audit metadata already exposed by `GET /v1/audit/events`.
- `status_version` returns existing local daemon version/status metadata.
- `sustainability_summary` returns aggregate local sustainability proxy estimates, defaulting to `30d`.
- The observability tools are read-only and local-only. They do not add model controls, runner controls, config changes, cloud fallback, command execution, prompt/resource/sampling support, remote transports, telemetry, persistence, uploads, or external lookups.
- This is not a complete MCP implementation and is not broad MCP client compatibility.

## API/Schema Hardening

- Local preview schema locks cover health, model manifests, model/runner status hints, daemon version/status metadata, audit events, sustainability metrics, invalid sustainability period errors, chat completion response shapes, and MCP response envelopes.
- Chat completion schema locks cover non-streaming responses, streaming SSE chunks, route metadata, local-only route flags, UTF-8-safe streaming fragments, and representative invalid input errors.
- MCP tests cover initialize, tools/list, route_explain success/error payloads, read-only observability tool success/error payloads, notification no-response behavior, and JSON-RPC error envelopes.

## Sustainability/Reporting Updates

- Sustainability metrics remain local-only aggregate estimates derived from local audit metadata.
- Aethra sustainability reports remain browser-generated from displayed metrics.
- Reports exclude prompts, raw request text, raw audit event bodies, PII, machine identifiers, hostnames, usernames, filesystem paths, secrets, and API keys.
- Sustainability values are estimated, counterfactual, proxy, methodology-dependent, and low-confidence preview indicators.
- They are not measured energy use, not actual carbon accounting, not ESG certification, not certified sustainability reporting, and not production compliance evidence.

## Contributor/Repo Cleanup

- Contributor templates and docs navigation were tightened for local-first review.
- Release and testing docs now point reviewers toward the local preview diagnostics, schema locks, Aethra checks, sustainability language guardrail, and artifact hygiene checks.
- Adapter docs remain planning material. The LiteLLM-style local gateway is a future plan, not implemented. DreamServer remains concept-only and is not current implementation work.
