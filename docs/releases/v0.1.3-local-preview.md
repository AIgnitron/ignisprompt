# Local Preview v0.1.3 Release Readiness

Release status: draft. `v0.1.2-local-preview` remains the current latest local-preview release. This document prepares the next local preview release package after `v0.1.2-local-preview`. Do not tag or publish `v0.1.3-local-preview` yet.

## Summary

`v0.1.3-local-preview` is the next narrow local preview release package after `v0.1.2-local-preview`. The focus is local operator visibility and local evidence hygiene: more inspectable CLI output, stricter local bundle validation, better bundle metadata, and release documentation that stays conservative about what the current scaffold does.

The default path remains local-only and no-model friendly. It does not require Ollama, GGUF tooling, external model weights, cloud credentials, telemetry, or external services for the default build/test/smoke workflow.

## What Changed Since v0.1.2-local-preview

- Added the contributor MCP usage guide for manual stdio MCP inspection and current tool-scope boundaries.
- Added the Aethra public demo package for a conservative public-facing local preview sequence.
- Hardened route-policy regression coverage for legal Tier 3 routing, general local routing, adversarial document-instruction handling, conservative explanations, and local audit emission.
- Hardened model availability semantics, model and runner status hints, and the feature-gated GGUF subprocess contract.
- Hardened the Golden Legal adversarial demo path, including the small synthetic fixture matrix and demo transcript behavior.
- Hardened audit evidence validation and the local-only attestation self-test path.
- Added feature-gated GGUF subprocess timeout handling and local runner preflight hardening while keeping `StubLegalRunner` as the default fallback.
- Hardened Aethra live-local contracts with fixture/schema contract tests, optional-field tolerance, model and runner status hint summaries, audit proxy estimate coverage, sustainability report redaction, and minimal docs cleanup.
- Added reproducible local security review checks for hidden Unicode scanning, conservative local secret scanning, optional `cargo-audit`, and optional SBOM dry-run/generation under ignored local evidence.
- Added `ignispromptctl` local inspection commands for `audit-events` and `route-explain`.
- Added `ignispromptctl evidence-bundle` generation from local endpoints only.
- Added `ignispromptctl evidence-bundle --list` and `ignispromptctl evidence-bundle --validate` for read-only bundle inspection without daemon access.

## CLI and Bundle Notes

- `ignispromptctl audit-events` and `ignispromptctl route-explain` stay local-only inspection commands. They do not add telemetry, cloud calls, uploads, global aggregation, or remote execution.
- `ignispromptctl evidence-bundle` writes a local-only bundle under ignored `local-evidence/` paths and uses the existing local health, version, model, model and runner status hint, and sustainability endpoints.
- `--include-audit-events` stays explicit. `--json` prints structured JSON. `--list` and `--validate` operate on an existing bundle directory and do not call the daemon.
- Bundle metadata stays conservative: local preview only, local-only, non-certified, not signed, and not production attestation.

## Aethra Local Preview Improvements

- Fixture mode remains the default.
- Live-local loading remains manual and loopback-oriented.
- The local preview banner keeps the no-telemetry, no-cloud-by-default, non-production boundary visible.
- Overview diagnostics continue to distinguish fixture mode, live-local readiness, successful local connection, unreachable daemon, unavailable endpoints, invalid response shapes, failed refreshes, and successful refreshes.
- Local command helpers remain copy-only browser clipboard actions. Aethra does not execute commands.
- Empty states continue to explain missing fixture or live-local data and the next local action to try.

## MCP Improvements

- The experimental stdio MCP stub still uses newline-delimited JSON-RPC over stdio.
- `tools/list` advertises `route_explain`, `audit_events`, `status_version`, and `sustainability_summary`.
- The observability tools remain read-only and local-only. They do not add model controls, runner controls, config changes, cloud fallback, command execution, prompt/resource/sampling support, remote transports, telemetry, persistence, uploads, or external lookups.
- This is not a complete MCP implementation and is not broad MCP client compatibility.

## API and Schema Hardening

- Local preview schema locks cover health, model manifests, model and runner status hints, daemon version and status metadata, audit events, sustainability metrics, invalid sustainability period errors, chat completion response shapes, and MCP response envelopes.
- Chat completion schema locks cover non-streaming responses, streaming SSE chunks, route metadata, local-only route flags, UTF-8-safe streaming fragments, and representative invalid input errors.
- The audit-events and route-explain CLI coverage remains read-only and local-only.

## Sustainability and Reporting Updates

- Sustainability metrics remain local-only aggregate estimates derived from local audit metadata.
- Aethra sustainability reports remain browser-generated from displayed metrics.
- Reports exclude prompts, raw request text, raw audit event bodies, PII, machine identifiers, hostnames, usernames, filesystem paths, secrets, and API keys.
- Sustainability values are estimated, counterfactual, proxy, methodology-dependent, and low-confidence preview indicators.
- They are not measured energy use, not actual carbon accounting, not ESG certification, not certified sustainability reporting, and not production compliance evidence.

## Contributor and Repo Cleanup

- Contributor templates and docs navigation remain focused on local-first review.
- Release and testing docs point reviewers toward the local preview diagnostics, schema locks, Aethra checks, sustainability language guardrail, security review helpers, and artifact hygiene checks.
- Adapter docs remain planning material. LiteLLM-style local gateway work remains a future plan, not implemented. DreamServer remains concept-only and is not current implementation work.
