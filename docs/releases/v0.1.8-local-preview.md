# Local Preview v0.1.8 Release Prep

This is a release-prep record for a future `v0.1.8-local-preview` tag. It does not tag, publish, or announce v0.1.8. The latest published local preview release remains `v0.1.7-local-preview` until a separate tag and GitHub Release are created.

IgnisPrompt and Aethra remain local-preview software. The default path makes no cloud calls by default, sends no telemetry, performs no global aggregation, and does not require Ollama, GGUF tooling, model weights, cloud credentials, or external runners for the default build, test, and local smoke paths.

## Release Focus

v0.1.8 prepares the Local Demo Studio arc for a future local preview release:

- Aethra Local Demo Studio for fixture-backed, read-only local preview walkthrough review.
- `ignispromptctl demo-summary` for local preview demo story guidance without daemon access.
- Human, `--json`, and `--report` output for copy-safe local demo review notes.
- Demo package output, list, and validate workflow under ignored `local-evidence/demo-studio/`.
- Safe demo package contents with README, manifest, JSON summaries, and Markdown report output.
- Read-only demo package preview in Aethra.
- Copy-safe demo report snippets in Aethra.
- `scripts/demo-check.sh` and `make demo-check`.
- `make dev-check` integration through the local preview validation flow.
- Demo workflow integration through `scripts/demo-local-evidence-workflow.sh`.
- Local Demo Studio hardening from PR #188.
- Shared package and path validation hardening across demo, policy, operator, readiness, and evidence workflows.
- Stricter demo package validation for absolute paths, parent traversal, symlink traversal, unexpected files, symlinked required files, unsafe content, malformed JSON, schema drift, and placeholder-like values.
- CLI and Aethra conservative language parity for local preview boundaries.
- `make preview-release-check` as a local preview validation helper.
- Public CI coverage through the default-path and Aethra jobs.

## CLI Notes

`ignispromptctl demo-summary` stays a local preview demo helper. It does not call the daemon, execute a model, upload data, persist browser state, or publish artifacts.

The command supports:

```bash
cargo run -p ignispromptctl -- demo-summary
cargo run -p ignispromptctl -- demo-summary --json
cargo run -p ignispromptctl -- demo-summary --report
cargo run -p ignispromptctl -- demo-summary --package-output local-evidence/demo-studio/demo
cargo run -p ignispromptctl -- demo-summary --package-list local-evidence/demo-studio/demo
cargo run -p ignispromptctl -- demo-summary --package-validate local-evidence/demo-studio/demo
```

The output keeps these boundaries visible:

- local preview demo only
- synthetic story steps only
- route, status, and package values are hints, not guarantees
- local helper checks are checks, not certification
- package validation is structural and local only
- demo packages are not signed
- no cryptographic verification
- no tamper-evident claim
- no telemetry
- no cloud calls by default
- no global aggregation
- Aethra is fixture-backed by default with manual live-local loading

## Aethra Notes

Aethra Local Demo Studio remains fixture-backed by default and read-only. Manual live-local loading remains explicit elsewhere in Aethra.

The Local Demo Studio does not add polling, command execution, file upload, a local file picker, archive extraction, arbitrary local path reads, localStorage or sessionStorage persistence, telemetry, cloud calls, global aggregation, model controls, or runner controls.

## Demo Package Validation

Demo package output is expected under ignored `local-evidence/demo-studio/` paths. Packages are local-only helper outputs for preview review and demo notes. They are not signed, not production evidence, not release approval, and not an attestation.

Validation is structural and local only. It checks required files, valid JSON, schema and version fields, package type and mode, expected generated file names, expected story step count, conservative boundary language, placeholder-like values, malformed JSON, schema drift, unsafe Markdown or script-like text, terminal escape and control characters where practical, absolute paths, parent traversal, symlink traversal, unexpected files, and symlinked required files.

Validation does not provide certification, legal accuracy review, compliance approval, security approval, supply-chain assurance, signed attestation, tamper-evident audit storage, cryptographic verification, or production deployment approval.

## Conservative Boundaries

## Release Safety

This docs PR must not change daemon runtime behavior, CLI behavior, Aethra runtime behavior, public HTTP response shapes, or product features. It must not tag v0.1.8 or publish a GitHub Release.

Generated evidence bundles, readiness packages, operator packages, policy packages, demo packages, archives, audit logs, demo reports, model weights, `target/`, SBOM outputs, root `dist/`, and `apps/aethra/dist/` must stay ignored and uncommitted.
