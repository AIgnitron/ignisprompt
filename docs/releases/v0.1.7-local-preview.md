# Local Preview v0.1.7 Release

Release status: published local-preview release record. `v0.1.7-local-preview` has been tagged and published. `v0.1.6-local-preview` was the previous published local-preview release.

## Summary

`v0.1.7-local-preview` records the post-v0.1.6 local policy workbench arc for this published local-preview release. The focus is synthetic policy scenario inspection, policy package workflow parity across CLI and Aethra, deterministic policy checks, demo workflow alignment, and recent local runtime hardening.

This release record documents the published local-preview scope. It does not move release tags, republish the GitHub Release, or claim production readiness.

The default path remains local-only and no-model friendly. It does not require Ollama, GGUF tooling, external model weights, cloud credentials, telemetry, global aggregation, or external services for the default build/test/smoke workflow.

- Added `ignispromptctl policy-scenarios` for synthetic local policy scenario inspection.

- Added local policy package output, list, and validate behavior under ignored `local-evidence/policy/` paths.
- Added safe policy package Markdown and JSON summary files.
- Added Aethra read-only policy package preview from fixture-backed data.
- Expanded synthetic policy scenarios for local tasks, sensitive local tasks, helper requests, sustainability preview requests, unsupported cloud-required requests, and ambiguous sensitive requests.
- Added grouping helpers and grouping metadata for CLI JSON, CLI Markdown, and Aethra policy summaries.
- Added CLI/Aethra parity checks for policy terminology and report/package assumptions.
- Added `scripts/policy-check.sh` and `make policy-check`.
- Integrated `make policy-check` into `make dev-check`.
- Extended the local evidence demo workflow to include policy package generation, listing, validation, and self-test coverage.
- Added stricter policy package validation, redaction, placeholder rejection, and path-safety checks.
- Preserved recent hardening from #182: Aethra public CI coverage, local daemon CORS/bind boundary checks, feature-gated GGUF blocking-task isolation, and AuditStore durability ordering.
- Preserved post-v0.1.6 hygiene hardening from #180 and #181 for package workflow test isolation, release-state docs alignment, changelog cleanup, and root ignore hygiene.

## CLI Notes

- `ignispromptctl policy-scenarios` remains local preview policy guidance only.
- `ignispromptctl policy-scenarios --json` emits safe structured policy scenario metadata without prompts, raw audit text, generated evidence contents, daemon URLs, hostnames, usernames, absolute filesystem paths, private credentials, or local machine-specific values.
- `ignispromptctl policy-scenarios --report` emits a copy-safe Markdown report for local demo or issue notes.
- `ignispromptctl policy-scenarios --package-output local-evidence/policy/<name>` writes a local policy package under an ignored path.
- `ignispromptctl policy-scenarios --package-list local-evidence/policy/<name>` inspects package files locally.
- `ignispromptctl policy-scenarios --package-validate local-evidence/policy/<name>` runs structural/local package validation only.
- Policy scenarios are synthetic route hints, not guarantees.
- Policy packages are local-only helper outputs. They are not signed, not certification, not attestation, not production evidence, and not release approval.

## Aethra Notes

- Aethra remains fixture-backed by default.
- Live-local loading remains manual.
- Aethra Local Policy Workbench remains read-only.
- Aethra policy package preview is a read-only local preview aid.
- Aethra policy report snippets are copy-safe local helper text only.
- Aethra does not execute commands, upload packages, extract archives, read arbitrary local paths, persist policy data, poll, add telemetry, add cloud calls by default, add global aggregation, or add model or runner controls.

## Policy Package Notes

- Package output must stay under ignored `local-evidence/policy/` paths.
- Package files are intended for local preview review and demo notes.
- Package validation is structural local validation only.
- Validation checks required files, JSON shape, schema fields, boundary terms, placeholder-like values, unsafe content, and unsafe output paths.
- Package validation does not provide certification, compliance approval, release approval, signed attestation, tamper-evident audit storage, cryptographic verification, supply-chain certification, or production deployment approval.
- Generated policy packages, policy reports, operator packages, readiness packages, evidence bundles, archives, audit logs, local evidence, model weights, SBOM outputs, `target/`, root `dist/`, and Aethra `dist/` output must stay ignored and uncommitted.
