# Local Preview v0.1.5 Release Readiness

Release status: draft. `v0.1.4-local-preview` remains the current latest local-preview release. This document prepares the next local preview release package after `v0.1.4-local-preview`. Do not tag or publish `v0.1.5-local-preview` yet.

## Summary

`v0.1.5-local-preview` is a narrow local preview release-readiness package for the local readiness arc after v0.1.4. The focus is Aethra Local Readiness, `ignispromptctl readiness`, readiness quality gates, copy-safe readiness reports, diagnostics, and local readiness packages.

The default path remains local-only and no-model friendly. It does not require Ollama, GGUF tooling, external model weights, cloud credentials, telemetry, global aggregation, or external services for the default build/test/smoke workflow.

## What Changed Since v0.1.4-local-preview

- Added the Aethra Local Readiness dashboard for fixture-backed local preview readiness cards, copy-only daemon guidance, and conservative checklist language.
- Added the local readiness quality gate through `scripts/readiness-check.sh` and `make readiness-check`.
- Added `ignispromptctl readiness` and `ignispromptctl readiness --json` over the existing local doctor checks.
- Added copy-safe local readiness report export through CLI Markdown output and Aethra browser-local report snippets.
- Improved local readiness diagnostics with safe category, severity, result, local next-step, and boundary-note fields.
- Added the local readiness package workflow under ignored `local-evidence/readiness/` paths.
- Added readiness package Markdown and JSON summary output, plus local list and validate behavior.
- Extended the local evidence demo workflow and readiness regression check to cover readiness package generation and validation.
- Added Aethra read-only readiness package and report preview from fixture-backed data.

## CLI Notes

- `ignispromptctl readiness` remains local preview readiness only.
- `ignispromptctl readiness --json` emits safe diagnostics without daemon URLs, hostnames, usernames, absolute filesystem paths, prompts, raw audit text, generated evidence contents, private credentials, or local machine-specific values.
- `ignispromptctl readiness --markdown` emits a copy-safe local helper report for issue or demo notes.
- `ignispromptctl readiness --package-output local-evidence/readiness/<name>` writes a local readiness package under an ignored path.
- `ignispromptctl readiness --package-list` and `ignispromptctl readiness --package-validate` inspect local readiness packages without daemon access.
- Readiness packages are local-only helper outputs. They are not signed, not certification, not attestation, not production evidence, and not release approval.

## Aethra Notes

- Aethra remains fixture-backed by default.
- Live-local loading remains manual.
- Aethra Local Readiness remains read-only.
- Aethra command snippets remain copy-only. The dashboard does not execute commands.
- Readiness cards and diagnostics remain status hints, not controls.
- Aethra readiness reports and package previews are browser-local copy helpers only.
- Aethra does not upload, persist, poll, add telemetry, add cloud calls by default, add global aggregation, or add model or runner controls.

## Readiness Package Notes

- Package output must stay under ignored `local-evidence/readiness/` paths.
- Package files are intended for local preview review and demo notes.
- Package validation is structural local validation only.
- Package validation does not provide certification, compliance approval, release approval, signed attestation, tamper-evident audit storage, cryptographic verification, supply-chain certification, or production deployment approval.
- Generated readiness packages, readiness reports, archives, audit logs, local evidence, model weights, SBOM outputs, `target/`, and Aethra `dist/` output must stay ignored and uncommitted.

- Preserve adversarial document-instruction handling.

- Do not change daemon runtime behavior, CLI behavior, Aethra runtime behavior, or public HTTP response shapes as part of release-prep docs.
